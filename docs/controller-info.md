# Read-only controller information v1

`bus/{busId}/{devId}/controller-info-v1` returns a diagnostic snapshot for the selected virtual device. The authenticated API's normal access policy applies. The request has no payload, makes no controller writes and cannot forward an arbitrary USB setup packet. It does not reopen streams, allocate controllers or advance input counters.

The version-1 response contains `busId`, `devId`, device `type`, numeric `vendorId`, `productId`, `usbRevision` (the USB device revision, not USB protocol version), descriptor `manufacturer`, `product`, `serial`, and a filtered `metadata` object. Device creation options, registration/removal capabilities and application paths are not returned.

Sony devices additionally include `factoryReport`, encoded as JSON base64. Its bytes are generated by the same USB GET_REPORT handler exposed to the host: DS4 feature 0xA3 (49 bytes), or DualSense/Edge 0x20 (64 bytes). These reports are read-only. Hardware/firmware fields describe the virtual persona and must not be presented as the physical controller's identity or the application's build date.

Xbox One additionally provides public immutable GIP identity fields in `details`: `firmwareVersion`, `hardwareVersion` and `deviceInfo`. No activation or removal tokens are included. Other output types retain their actual USB descriptor and supported status metadata; a missing firmware field must remain unavailable rather than being invented.

The UI should bind the reply to the same physical controller and active virtual stream that initiated the request, discard replies after either changes, and use bounded asynchronous queries. This endpoint is intended for explicit snapshot refreshes, not the input-report hot path.

Tests exercise all stable virtual controller families, compare Sony bytes against their actual USB handlers, keep same-model devices separate, reject writes/invalid identities, preserve metadata and device lifecycle, and ensure Xbox One public versions do not leak operation authority.
